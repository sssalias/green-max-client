Green Max Client

Гайд по локальному запуску

Инструкция для запуска проекта в режиме разработки и проверки production-сборки.

1. Требования

  • Node.js 20 или новее.
  • Yarn или npm.
  • Доступ к Green API.

2. Установка проекта

Перейдите в каталог проекта и установите зависимости:

yarn install

Альтернативный вариант через npm:

npm install

3. Настройка окружения

Создайте локальный файл .env из шаблона:

macOS/Linux:

cp .env.example .env

Windows PowerShell:

Copy-Item .env.example .env

В файле должна быть указана базовая ссылка API:

VITE_API_URL=https://3100.api.green-api.com
Важно: файл .env используется локально и не должен добавляться в Git. Для проекта уже подготовлен безопасный шаблон .env.example.

4. Запуск в режиме разработки

Запустите dev-сервер:

yarn dev

или:

npm run dev

Откройте адрес из вывода Vite. Обычно это:

http://localhost:5173

На странице авторизации введите idInstance и apiTokenInstance Green API.

5. Проверка production-сборки

Соберите приложение:

yarn build

Предпросмотр собранного приложения:

yarn preview

Проверка кода линтером:

yarn lint
Важно: переменная VITE_API_URL встраивается в JavaScript во время сборки. Изменение .env требует перезапуска dev-сервера или повторной production-сборки.

6. Локальный запуск через Docker

Соберите production-образ:

docker build -f Dockerfile.local -t green-max-client-local .

Запустите контейнер:

docker run --rm -p 3000:3000 green-max-client-local

Приложение будет доступно по адресу:

http://localhost:3000

7. Частые проблемы

Изменения не отображаются

Перезапустите dev-сервер. Для production удалите старую сборку и выполните yarn build заново.

API использует старый адрес

Проверьте значение VITE_API_URL и пересоберите приложение. В уже созданном Docker-образе переменные окружения не меняются после запуска контейнера.

Зависимости устанавливаются с ошибкой

Проверьте версию Node.js, наличие доступа к registry и повторите установку через пакетный менеджер, указанный в lock-файле проекта.
